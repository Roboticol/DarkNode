DarkNode Multi-Layer GNN Architecture & Inference Specifications
MATHEMATICAL FORMULATION & PIPELINE TOPOLOGY

1. Heterogeneous Multi-Layer Graph Schema

Mule account syndicates operate across diverse entity layers to conceal illicit fund movements. Standard transactional rules examine accounts in isolation, failing to detect structural multiplexing. DarkNode structures financial activity as a heterogeneous graph G = (V, E, T):

• Entity Nodes (V):
- Users (V_U): Individual account holders initiating and receiving financial transactions.
- Devices (V_D): Hardware fingerprints (IMEI, MAC, browser hardware hashes) shared across accounts.
- Merchants (V_M): Payment gateway terminals and merchant entities receiving burst settlements.
• Relational Edges (E):
- (u_i → [TX: Transfers] → u_j): Peer-to-peer money transfers with timestamp, velocity, and amount attributes.
- (u_i → [DEV: Uses Device] → d_k): Account access from shared hardware, detecting mule multiplexing.
- (u_i → [IP: Subnet Match] → u_l): IP/subnet collision edges identifying co-located operators.
- (u_i → [MERCH: Settlement] → m_p): Target merchant transactions capturing high-frequency cash-outs.

2. Mathematical Formulation: 2-Layer Relational MPNN

DarkNode implements relational message passing across all edge types R. At layer l in {1, 2}, node representations are updated via directional aggregation:

m_{N(v)}^{(l)} = AGGREGATE_{r in R} ( Σ_{u in N_r(v)} W_r^{(l)} · h_u^{(l-1)} )
h_v^{(l)} = LeakyReLU( W_{self}^{(l)} · h_v^{(l-1)} + m_{N(v)}^{(l)} )

Why exactly 2 Layers? Layer 1 captures direct 1-hop associations (e.g. User to Shared Device). Layer 2 captures indirect 2-hop structural coordination (User A → Device → User B → Merchant) essential for catching distributed smurfing rings without inducing topological over-smoothing.
